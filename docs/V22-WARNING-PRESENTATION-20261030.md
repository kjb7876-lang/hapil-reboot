# v22 광선 예고 표시 수정

v21의 `drawHazards`는 실제 광선과 달리 해당 예고의 시전자·보조색 슬롯을 팔레트 조회에 전달하지 않았다. 한리안·백이온 합일 회로의 백이온 예고도 기본 한리안 팔레트를 선택할 수 있었다. 실제 코어가 만든 백이온 경고를109틱에서 관찰하고, 해당 객체를 조회에 전달하도록 고쳤다. 예고와 활성 본체가 같은 소유자·팔레트 슬롯을 해석한다.

폭이18px 이상인 예고는 실제로 피해가 생길 캡슐의 외곽을 표시한다. 기존 희미한 전체 폭 채색과 중심 점선은 유지하고, 반경보다1.25px 안쪽에2.5px 어두운 선과1.4px 소유자색 선을 겹쳤다. 어두운 선의 바깥끝은 실제 반경에 닿으며, 더 넓은 위험 구역이나 이동하는 조준 경로를 만들지 않는다. 아직 안전한 경고는 점선 중심·얇은 경계로, 활성 광선은 기존 원화 픽셀로 구분한다. 넓은 광선의 경고 전체에 원화 유령을 추가하는 안은 화면을 더 덮고 비용이 늘 수 있어 적용하지 않았다.

첫 후보의.9px 밝은 경계는 타락천사 기사 돌바닥의 부분 좌표에서 약25.8%만 강한 대비를 보여 독립45% 기준을 통과하지 못했다. 같은 원래 색과 같은 실제 폭을 유지하고 경계선만1.4px로 넓힌 비공개 비교에서65.8%를 확인했다. 기준을 낮추거나 특정 보스만 예외 처리하지 않았다.

코어·저장·공격 원화·활성 광선 렌더링은 이 수정에서 바꾸지 않았다. `src/projectiles.js`는 v21 배포와 바이트가 같다. 렌더러는 본체가 활성화되는 정확한 코어 틱에 경고 외곽 표시를 멈춘다. 플레이어 피격점의 기존 밝은 점·어두운 테두리와 최상단 그리기도 유지한다.

경고 관찰 레코드와 배열은 렌더러별 풀을 재사용한다. 매번 프레임마다 캡슐 좌표 객체를 새로 쌓지 않는다. 진단 요청에서만 안정된 스냅샷을 복사한다. 게임의 기존 최대40개 광선 한도에 의해 기록 수도 제한된다.

`tests/warning-presentation-v22.test.cjs` 두 검사가 실제 시전자 전달,9개 실제 형상/난도 경고 직전 상태, 상·하 품질, 경고→활성 경계, 상태 불변 및 반복 렌더 기록 재사용을 확인했다. 기존 자기 원화 분신·공격체 검사5개도 통과했다. 이 상태 관찰은 외부 무적을 사용한 표시 fixture이며 자연 진행·사람 플레이·실제 브라우저·GPU·휴대폰 FPS 결과가 아니다. 독립 픽셀 차이 검수는 별도의 `V22-WARNING-PIXEL-REVIEW-20261030.json`에 기록한다.

최종 독립 픽셀 검수48사례(8개 대표 원화 구성×3난도×상/하 품질)가 같은 기준을 통과했다. 노출된 실제 경계 안쪽의 강한 대비 비율은 최소49.84%, 앞서 약했던 기사 헬 장면은65.79%였으며 기존 기준45%를 유지했다. 실제 캡슐 바깥1.1px 안티앨리어싱 허용 범위를 넘는 추가 칠하기는0이었다. 제작 담당자도 최종8개 헬 원화의 이전/수정 접점을 직접 확인했고, 어두운 돌바닥과 밝은 금빛 바닥에서 경계와 캐릭터·탄환이 함께 읽히는 것을 확인했다. 활성 광선과 탄환 본체는 기존 자산 그대로다.
