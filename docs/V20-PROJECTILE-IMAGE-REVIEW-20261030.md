# V20 탄환 이미지 검수와 캐시 개선 — 2026-10-30

v19의 실제 탄환 원본과 전체 37개 표시 경우의 픽셀을 다시 확인했다. 기존에 해결한 사각 배경 카드와 소유자 혼용은 재발하지 않았다. 이번 개선은 실제 실행에서 쓰는 소수 반경·방향·부분 픽셀 좌표와 밝은 배경에서의 경계에 집중했다. 물리 판정·탄속·서사·저장 코드는 변경하지 않았다.

## 적용

- 작은 자산 탄환의 원래 알파에서만 경계를 추출해 어두운 테두리를 캐시에 한 번 굽는다. 3배 캐시의 8방향 인접 픽셀을 사용하므로 가장 먼 대각 경계도CSS 0.48px 미만이다. 원래 불투명 픽셀은 그대로 보존한다. 전체 장식 범위는 기존 4px 이내이며, 실제 화면에서는 여전히 탄환당 이미지 한 번만 그린다. 그림자·필터·픽셀 처리를 매 탄환/프레임에 반복하지 않는다.
- 소수 반경 3.8 등의 캐시 중심을 짝수 표면의 정확한 중심에 맞춘다. 표면 원점의 비대칭 재표본화를 줄이며 원화의 외곽과 물리 반경은 유지한다.
- 두 번째 색상을 쓰는 탄환의 팔레트 객체를 소유자 원본 객체 기준 WeakMap으로 재사용한다. 색 값은 바뀌지 않으며 서로 다른 시전자의 팔레트를 공유하지 않는다.
- 악몽 우두머리 자신의 곡검은 실제 불투명 영역으로 중심을 맞춘다. blade anchor만 `[288,269]→[288.5,269]`로 조정했다. 인접한 원본 x288/289, y268~270은 모두alpha255다. 어두운 테두리만으로 중심 판정을 채우는 대신 실제 색이 있는 검의 중심을 맞췄다.
- 한리안의 긴 탄환은 원래 진행 방향과 물리 캡슐 방향으로 회전한다. orb의 고정 방향은 유지하고blade의 `fixedOrientation`만false로 변경했다.

새 단일 기준은 `docs/V20-STORY-PROJECTILE-CONTRACTS-20261030.json`이다. 과거 V19 JSON은 보존했다. 기존 생성기의 명시적 입력으로 `python tools/build-story-visual-contracts-v19.py --projectiles docs/V20-STORY-PROJECTILE-CONTRACTS-20261030.json`을 실행하면 현재 provider를 재생성한다. v19 provider와 데이터 차이는 위 두 필드뿐임을 독립 비교했다.

## 반복 검수 근거

처음 대표 3/6 반경 검사는 통과했지만, 실제 실행에서 나온 3.8/4 반경과 9/13 길이를 추가하자 4가지 중심 누락과 한리안의 방향 불일치를 발견했다. 독립 실제 216전투 관찰로 94개 실제 모양/소유자 조합을 모았다. 5개 방향·부분 픽셀 배치와2개 색으로 확장한940행의 같은 기준에서 이전 78개 실패가 현재 0개가 됐다. 중심 alpha180 이상 80% 기준은 낮추지 않았으며 최솟값은83.33%다. 원래 문제였던 4모양은 실제 밝은 원본 색을 가진 중심 픽셀도 80% 이상으로 확인했다. 테두리의 어두운 픽셀만으로 가독성 검사를 통과했다고 처리하지 않았다.

보라검천사·루시퍼의 원본 4프레임은 각각 0/.125/.25/.375초로도 확인했다. 실제 반경·부분 좌표·색·방향의 중심과 외곽 조건이 통과했고 마지막 원본 프레임 유지도 확인했다. 정적인 나머지 원본을 연속 애니메이션으로 부르지 않는다. 상세 독립 근거는 `V20-ACTUAL-PROJECTILE-PIXELS-20261030.json` 및 해당 QA 문서를 참조한다.

`tools/review-source-edge-v20.cjs`는 같은 현재 소유자 데이터와 실제 원본 그림의 두 부분에 v19/v20 코드를 그린다. 원래 크기와 4배 확대를 함께 저장하며 코드·미디어 해시가 검수 중 바뀌면 결과를 게시하지 않는다. `v20-pixels/source-edge-own-map-ab.jpg`의 실제 픽셀을 직접 확인했다. 밝은 아르벨리아 바닥과 우두머리의 흰 바닥에서 곡선·가느다란 탄체의 경계가 더 분명했고, 원본 색과 모양을 유지했다. 이 접촉표는 원본 그림 부분의CPU 비교이며 전체 전투 장면·브라우저·자연 진행 검사로 부르지 않는다.

## 비용과 한계

알파 테두리는 캐시 생성 비용을 조금 늘린다. 별도 네이티브Node 프로세스에서 이미지를 미리 디코딩하고 매번6개 캐시를 새로 만드는 20표본을 비교했다. 7개 소유자별 중앙값은 v19 1.82~3.40ms, v20 3.07~5.54ms였다. 6개 캐시 기준 증가량 0.83~2.59ms이며, 매 프레임 비용이나 휴대폰 시간으로 환산하지 않는다. 이 결과는 `V20-PROJECTILE-COLD-CACHE-CPU-20261030.json`에 기록했다. 초기 VM/네이티브를 섞은 비교는 무효로 분리했고 근거로 사용하지 않았다.

실제 휴대폰·GPU·장시간 FPS·사람 플레이는 이 이미지 검수의 범위가 아니다. 실제 회피 가능성과 저장은 별도 엔진/입력 검사, 최종 브라우저와 성능은 루트 보고서의 범위다.
