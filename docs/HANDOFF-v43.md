## 1. 다음에 할 일 (사용자의 마지막 요청 원문)

> 1. 구글드라이브에 일반몹자산 보스몹자산 무기자산 조형물 및 타일등 엄청많은데 보상으로 쓸만한자산도 많고 왜 모션들이나 이러한자산들 사용안하는거야
> 2. 테마변화가 없어 맵이 거의 똑같아 일반맵도 똑같고 그리고 스테이지가 너무적어 스토리모드 에피소드만으로도 스테이지 수십개 만들 수 있지 않나? 7대죄만으로도 7-10개는 만들겠는데 총플레이타임 3-4시간정도 잡게/동방탄막게임등 유명 탄막게임 벤치마킹해서 개선적용해줘 나중에 유료겜으로 팔거니까 모바일화도 많이 염두해둬서 모바일유명탄막게임도 벤치마킹하고 요새 잘나가는 세로모드 유명게임들도 참고해서 개선적용해줘

풀어 쓰면:

1. **드라이브 자산을 실제로 쓴다.** 일반 몹, 보스, 무기, 조형물, 타일, 보상용 자산, 모션(애니메이션 프레임).
   - v41에서 안 쓴 이유: 당시 지시가 "HOLD 표시 자산은 검토 뒤에만"이었고, 최신 CX- 납품(CX-0082MV, 0088FB, 0089SB, 0091SE, 0094MH, 0095GV, 0096HS 등)이 거의 다 HOLD였다. 이번 요청으로 사용 허가가 난 것으로 본다. 다만 HOLD 사유가 품질 문제인지 먼저 확인하고, 쓴 것과 안 쓴 것을 표로 남길 것.
   - 리포 `media/`(106MB)에도 아직 ARCADE가 안 쓰는 것이 많다: `media/maps/map01~12.webp`, `actors-v6`, `actors-v7`, `boss-motion-v8`, `sins-v13`(7대죄 아틀라스), `story-v19`(79개), `fx-v6`, `fx-v8`, `combat`, `encounter-signature-v11`. `src/story-assets.js`에 장면별 인물·프레임·탄 정보가 있다.
2. **스테이지를 수십 개로.** 원작 장면 55개를 기준으로 장면마다 스테이지 하나를 목표로 한다(7대죄만 7~10개). 총 플레이 3~4시간.
   - 지금은 9스테이지, 한 번 완주 약 18분.
3. **테마 변화.** 지금 배경 9장이 모두 어둡게 눌려 비슷해 보인다. 스테이지마다 맵·색조·잡몹·타일·조형물이 달라야 한다.
4. **벤치마킹 후 적용.** 동방 프로젝트류 탄막, 모바일 탄막 게임, 요즘 잘 되는 세로 모드 게임. 캐릭터·이름·패턴·그림·음악은 베끼지 않는다(구조와 감각만).
5. **유료 판매·모바일 전제.** 세이브/이어하기, 스테이지 선택과 해금, 보상, 성능, 용량.

## 2. 반드시 지킬 것 (사용자가 준 제약)

- 서사 내용 불변. 십자가는 똑바른 형태만(회전 금지). 미카엘라 기본탄은 하트.
- 글은 스테이지 이름 한 줄, 패턴 이름 한 줄만. 긴 대사·설명 자막·컷신 금지.
- 탄: 단색 속 + 밝은 테두리, 모양·색 5~6가지. 배경은 탄보다 어둡고 흐리게. 장식은 탄 뒤. 영웅 탄은 반투명.
- 공정성: 모든 패턴에 피격점이 지나갈 길이 항상 있어야 한다. 화면 밖에서 갑자기 나타나는 탄 금지.
- 성능: 오브젝트 풀, 탄 상한(모바일은 더 낮게, 대신 크게). 아이폰 13 미니 기준. 스테이지 전환 때 같은 그림 재다운로드 금지, 지난 스테이지 캔버스 폐기, 보스 등장 때 일괄 로드 금지. NaN/Infinity 방어.
- 소리 크기: 피격 > 폭탄 > 보스 패턴 시작 > 스침·아이템 > 사격 > 적 탄. 유료 결제가 필요한 생성 금지.
- 터치: 손가락이 영웅·피격점을 가리지 않게. 키 수를 늘리지 않는다.
- **main 직접 푸시, 강제 푸시, 테스트 수정·건너뛰기·결과 하드코딩 금지.** 같은 원인으로 세 번 연속 실패하면 멈추고 가설과 확률을 정리해 묻는다.
- 완료 조건은 먼저 실패하는 테스트로 쓰고, 실패를 확인한 뒤 코드만 고친다.
- 무한·협동·777 시험 모드·패시브 강화·사몽/EGO 각성은 넣지 않고 "다음 단계 후보"로만 적는다.
- 보고는 한국어, 짧게, 결론 먼저, 위험은 확률(%)로. 헤드리스 검증과 실제 플레이 확인을 구분해 적는다.
- 병합(배포)은 사용자가 "배포해"라고 할 때만.
- 커밋에 `node_modules/`, `package-lock.json`을 넣지 않는다.

## 3. 코드 지도

| 파일 | 역할 |
|---|---|
| `arcade.html` | 총집본 페이지. 모드(원큐 여정/보스 체험), 난이도, 시작 스테이지 선택 |
| `src/arcade-v38.js` | 시뮬레이션(60Hz 고정, 시드 난수, DOM 없음). `STAGE_DATA`, `spells`, `ACTORS`, `MOBS`, `PROPS`, `Shapes`, `createRun`, `step` |
| `src/arcade-app-v38.js` | 그리기·입력·소리. `loadStage`/`releaseStage`, `TALL`(그림 키 → 화면 높이) |
| `src/audio-v37.js` | 합성 효과음(`CUES`, `VOICE`). 옛 스토리판과 공용 |
| `media/arcade-v41/` | ARCADE용 그림 52장 + `manifest.json`(원본 경로·해시) |
| `tools/build-arcade-art-v41.py` | 위 그림을 리포 원화에서 만드는 스크립트 |
| `tests/arcade-v41.test.cjs`, `tests/arcade-v42.test.cjs` | 완료 조건 테스트(고치지 말 것) |
| `tests/helpers/arcade-lane.cjs` | 안전 통로 검사기(도달 가능 칸 전파) |
| `index.html`, `src/core.js`, `src/render.js`, `src/app.js` | 옛 스토리판. 테스트 562개가 묶여 있으니 전투·서사는 건드리지 않는다 |

스테이지를 늘릴 때 고칠 곳: `STAGE_DATA`(스테이지 정의) → 구간 생성기(같은 파일 아래쪽) → 앱의 `TALL`, `STAGE_COLOR`(지금 9칸 고정) → 그림 팩.

주의: v41 테스트 1번은 "스테이지 이름이 원작 장면 제목, `scenes`가 쉼터 제외 55장면을 순서대로 빠짐없이"를 요구한다. 장면당 1스테이지(55개)면 그대로 통과한다. v41 테스트 2번은 스테이지마다 `W M+ W B+` 구성과 보스 패턴 3개 이상을 요구하므로, 스테이지를 55개로 늘리면 이름 붙은 패턴이 220개 이상 필요하다. 이 조건이 새 설계와 맞지 않으면 테스트를 몰래 고치지 말고 사용자에게 먼저 물을 것.

## 4. 작업 방법 메모

- 테스트: `npm test`(약 11분, 얕은 클론이면 `git fetch --depth=1000 origin main` 먼저). 부분 실행은 `node --test tests/arcade-v41.test.cjs tests/arcade-v42.test.cjs tests/audio-v37.test.cjs`.
- 테스트가 `docs/v25-pixels`, `docs/v25-qa`를 덮어쓴다. 커밋 전에 `git checkout -- docs/v25-pixels docs/v25-qa`.
- 헤드리스 확인: Playwright + 크롬으로 `python3 -m http.server` 위에서 `arcade.html`을 띄운다. `HapilArcadeApp.debugState()`로 상태를 읽고 구간을 건너뛸 수 있다.
- 지금까지 확인 못 한 것: 실제 휴대폰 프레임·메모리, 사람 손 플레이, 소리. 보고할 때 항상 밝힐 것.

## 5. 제안하는 순서

1. 드라이브 자산 전수 목록(종류·파일·HOLD 여부·쓸 곳)과 리포 `media/` 미사용 목록 작성.
2. 벤치마킹 요약(탄막 3종, 모바일 탄막 3종, 세로 모드 인기작 3종)과 가져올 구조 정리.
3. 55장면 → 스테이지 표(테마·맵·잡몹·중간 보스·보스·패턴 이름·보상) 설계. 3~4시간이 되도록 스테이지당 길이 산정.
4. 사용자 확인이 필요한 결정(§3의 테스트 2번 조건, 패턴 수, HOLD 자산) 묻기.
5. 완료 조건 테스트 작성 → 실패 확인 → 구현 → 전체 테스트 → PR.
