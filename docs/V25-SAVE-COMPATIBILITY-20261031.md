# V25 진행 저장 호환성 검증

새 전투는 `combatRevision:25`를 명시한다. 기존 `21` 기록과 필드가 없던 기록은 같은 규칙으로 복원하며, 같은 실행의 체크포인트 저장으로 규칙을 바꿀 수 없다.

저장 레코드의 `combatContract`는 한 번 기록한 가장 높은 지원 버전으로 유지한다. 설정 저장, 기록 지우기, 패배 후 재시도, 이전 규칙으로 새 실행을 저장해도 25를 21로 내리지 않는다. 실제 배포된 기준 커밋 `945799615b35bb732ca5d6a0c48db8eebbd92a74`의 저장 모듈을 별도 VM에서 실행하여, 이미 열려 있던 21 클라이언트가 25 레코드에 설정·체크포인트·삭제·완료를 쓰려 할 때 모두 거부하고 원본을 내보내기에 보존하는지 확인했다.

정상 API가 만들 수 없는 같은 실행의 25/21 또는 25/필드 없음 혼합 체크포인트·백업은 쓰기를 막는다. 손상된 본 기록과 유효한 25 백업은 디스크를 자동으로 수정하지 않고 복원한다. 손상된 백업은 원본을 보존하고 쓰기를 막는다. 기존 21/필드 없음 검증 동작은 유지한다.

대상 검사 33개가 통과했다. 새 검사 7개와 기존 저장 검사 26개이며 실패·취소·건너뜀은 없다. 지연 중인 쓰기의 실제 커밋 이전 상태, 직렬 처리, 백업, 오래된 탭의 충돌, `peek`와 명시적 `load`의 차이, 쓰기 실패, 연습 기록 격리를 포함한다. 실행 시간은 923.26963ms였다.

일반 체력 3의 HELL 맘몬 연습에서 무적 값을 바꾸지 않고 합법적인 입력 600회로 저장 복원 전후 전체 월드를 매 단계 비교했다. 최소 120회의 진행 중인 전투를 검사하도록 조건을 두었다. 이는 저장 복원 결정론 검사이며 자연 진행 완주나 인간의 플레이 테스트를 뜻하지 않는다. 새 실행 알림은 앱에서 소비하는 일회성 UI 이벤트이므로 비교 전에 소비했다.

첫 실행은 33개 중 1개가 실패했다. 새 월드에는 비어 있는 `_identityPlans`가 있었지만 복원된 월드에는 없었다. 코어 담당자가 초기화를 일치시킨 뒤 같은 전체 월드 비교를 그대로 다시 실행하여 통과했다. 첫 실패 로그와 최종 로그를 모두 보존했다. 이 문서와 JSON은 해당 실행 시점의 파일 해시를 기록하며, 이후 코어 수정의 검증 결과를 대신하지 않는다.

분류는 구현 확인, CPU 시뮬레이션, 직렬 IndexedDB 모형 검사다. 실제 브라우저의 IndexedDB, 실제 기기, GPU, 모바일 FPS, 터치 지연은 이 검사로 검증하지 않았다.
