# V25 보스 탄환의 소유 자산과 표시 역할

색욕의 V24 구현을 유지하면서 나머지 전투 설정에 보스 자신의 자산을 연결했다. 이 문서는 탄환 표시 변경의 범위를 기록한다. 전투 설정 수를 새 인물 수나 보스 원본 목록 수로 환산하지 않는다. 서사·보호 대상·전투 순서는 `V25-CANONICAL-COMBAT-IDENTITIES-20261031` 문서에서 별도로 대조한다.

새 휴지·식칼·지폐·보물의 원본 및 256px 파생본 해시는 `V25-OWNED-OBJECT-SOURCES-20261031.json`과 `V25-RUNTIME-PROJECTILE-ASSETS-20261031.json`에 기록했다. 기존 질투 거울·탐욕 동전의 검증된 V24 자산도 유지한다.

## 피해 표시와 성능

새로 전체 물체를 적용한 원형 공격은 원본 RGB, 균일 배율, 측정한 불투명 피벗과 반지름을 사용한다. 일반 물체의 회전 전체 지름은 48px, 큰 물체는 100px 이내다. 추가 장식에 피해 판정을 만들지 않았다. 실시간에는 캐시된 몸체를 한 번 그리며, 도형 몸체나 다른 보스의 이미지를 뒤에 받치지 않는다.

가늘고 긴 기존 칼날·바늘은 원형 물체와 달리 긴 캡슐 피해 판정을 가진다. 원본 비율로 줄였을 때 피해 끝부분을 감추는 자산에는 전체 물체 방식을 강제하지 않았다. 검증된 기존 맞춤 방식과 자기 자산을 유지하며 원본 색과 역할 식별을 연결했다. 이들을 새로 완성된 균일 배율 물체라고 주장하지 않는다.

시간 제어 파편과 백이온 방패의 가는 기존 몸체는 원래 피벗·96px 샘플링을 유지한다. 원본 픽셀에만 `RGB × 1.5 + 90`의 노출 보정을 캐시해 밝기를 확보했다. 알파, 투명 부분, 윤곽, 피해 판정은 그대로다. 밝은 지점으로 피벗만 옮겼던 중간 후보는 전체 피해 영역의 가시성을 떨어뜨려 채택하지 않았다.

공통 캐시는 96개/4MiB 제한을 유지한다. 같은 전투의 같은 소스·반지름·역할을 다시 그릴 때 새 이미지를 처리하지 않는다. 회전 식칼의 소스 캐시는 여백을 확장하므로 손잡이와 칼끝을 잘라내지 않는다. 새로운 큰 회전탄의 공격 예고도 실제 발사될 물체를 보여준다.

색욕의 세 물체, 실제 반대 회전 부호로 고르는 발사 분기, 네 자세 자산은 그대로다. 보라검천사와 루시퍼의 기존 네 상태 ORB는 검증된 보스 팔레트 및 어두운 홍채·밝은 꽃잎 보정을 유지한다. V23 레이저 몸체·흐름·방출부·팔레트 경로도 그대로다. 네 자세를 완성된 연속 애니메이션으로 표현하지 않는다.

## 검증 자료

- `owned-projectile-identities-v25.test.cjs`: 소스 필수 로딩, 잘못된 크기 거부, 발사 단계별 소유 물체, 어린 기억 보호, 실제 반지름과 9회전에서의 전체 원형 피해 표시 90% 이상, 양 품질 동일 픽셀, 캐시 재사용, 식칼 소스 알파 보존, V24 색욕 및 V23 레이저 동일 픽셀을 검사한다. 36개 선택의 선택 로딩/필수 로딩 충돌도 검사하고, 발록의 실제 3단계×3난이도 발사를 수집해 모든 보조 원형탄을 9회전·양 품질에서 확인한다.
- 기존 V20 밝기 검사의 중심 알파·밝기 80% 및 이전 밝기 90% 기준을 유지했다. 검사에 맞추려고 기준을 낮추지 않았다. 두 가는 재료의 노출 보정은 5개 후보×144개 회전·소수점 위치·팔레트·품질 조합을 CPU 캔버스에서 비교해 선택했으며, 전체 피해 표시 90%도 함께 확인했다. 과정은 `V25-PROJECTILE-GRADE-PREFLIGHT-20261031.json`에 기록했다.
- 기존 V24의 ‘다른 보스 픽셀은 모두 같다’ 검사는 당시 V24 커밋으로 고정했다. 현재 V25의 바뀐 소스와 피해 표시 검사는 새로운 독립 검사에서 수행한다. 오래된 동전 선택 예시는 기억 단계로 명시해 보존했다.
- `V25-PROJECTILE-SOURCE-PROOF-20261031.json` 및 `v25-projectile-pixels/`: 각 보스 설정의 소스 몸체 전후 비교. 256px 투명 캔버스 중앙 128px 영역을 사용해 최대 100px 회전 물체를 접촉표에서 자르지 않는다.

이 자료는 구현 확인과 CPU 캔버스 검사다. 실제 브라우저·GPU·모바일 기기 성능이나 자연 진행 완주를 대신하지 않는다. 최종 통합 검사, 자연 진행과 배포 결과는 최종 QA 문서에 별도로 기록한다.
