## 확인한 원인과 수정

이전 코드는 보스별 원본 이미지를 사용했지만, 작은 불투명 내부 조각을 원·캡슐에 맞춰 늘이고 잘랐다. 7대죄의 구형/침형 탄환도 같은 재질 조각을 공유했다. 제3부도 같은 빔 중앙 조각을 양쪽에 사용했다. 원본 출처가 있다는 사실만으로 실제 탄환이 고유한 물체처럼 보이지 않았다.

일반 탄환의 캡슐 클립과 아홉 조각 늘이기를 제거했다. 보스 본인의 물체·무기·스킬 모티프를 한 번 작은 표면에 준비하고, 매 탄환은 캐시한 이미지 한 장만 그린다. 별도의 단색 원·캡슐·사각형 배경이나 외곽선을 그리지 않는다. 원본의 명암 차이와 투명한 끝·깃·가시·천의 윤곽을 남긴다. 절전 품질도 같은 탄환 픽셀을 쓴다.

기본 색은 보스 이름의 명시적 색, 실제 본체의 색, 본체 보조색 순이다. 이번에 선택한 일반 탄환 계약은 원래 투명한 알파 윤곽을 사용하며, 불투명한 배경 필드를 알파 증폭으로 바꾸거나 새로운 도형을 더하지 않는다. 원본 파일과 변환 정보는 자산 출처 문서 및 `src/story-assets.js`의 객체별 crop·anchor·색·방향·보정 값으로 추적한다.

## 충돌과 성능 계약

전투 엔진의 원·캡슐 충돌 반경, 속도, 가속, 수명, 레이저 예고와 피해 시점은 이 수정에서 바꾸지 않았다. 일반 탄환 그림은 작은 실제 판정 중심 바깥으로 최대 3~4 CSS 픽셀까지 뻗는다. 그 끝과 장식은 추가 피해 판정이 아니다. 큰 회전 무기에는 기존 34/36픽셀 장식이 별도로 남는다.

빈 중앙이 있는 복합 원화 전체를 무조건 축소하면 피격 중심이 사라질 수 있어 실제 픽셀로 다시 검사했다. 의미 있는 개별 물체를 골랐고, 시간 화살·방벽·교주 창의 중심도 실제 원본의 불투명한 부분에 맞췄다. 완전한 원본 마스터 피벗이라고 주장하지 않는 수동 게임용 기준점이다. 레이저의 작은 불투명 재질 조각은 판정 폭을 계속 드러내고, 본인 전체 원화가 그 위에 선명하게 표시된다. 일반 탄환에는 이 레이저용 조각이나 캡슐 바탕을 쓰지 않는다.

이미지 축소·회전·색 변환은 캐시를 만들 때만 한다. 실제 탄환 루프에서 원본 픽셀을 읽거나 고해상도 이미지를 다시 합성하지 않는다. 캐시는 최대 96개/4MiB이며 구간 변경·해제 시 표면을 반환한다. 정적인 원본 규격과 변환 키는 WeakMap으로 재사용해 매 탄환마다 규격 객체와 긴 문자열을 다시 만들지 않는다. 캐시 키에는 원본·crop·회전·프레임·축소 크기·중심·방향 고정·가공 옵션·색을 포함해 서로 다른 변환이 잘못 재사용되지 않게 했다.

## 검증 범위

`tests/independent-projectile-detail-v19.test.cjs`가 실제 원본을 디코딩하여 36개 선택과 교주전의 두 발사자를 검사했다. 각 경우 반경 3/6의 구형·침형, 두 품질에서 중심 12픽셀 중 80% 이상이 알파 180 이상인지, 원래 강제 캡슐 밖의 자연 윤곽과 내부 명암·색 변화가 남는지 확인했다. 일반 탄환은 실제 그림 한 번이며 도형 그리기 호출이 없고, 장식 범위·캐시 상한도 검사한다. 최종 파일에서 이 검사는 통과했다.
