# v25 활성 압박 구간의 면적·예고 취소 확인

기존 독립 CPU 도구 `tools/audit-attack-coverage-v21.cjs`의 `inspect`, `inspectWaves`, `curtainFraction`을 그대로 가져와 `combatRevision:25`로 실행했다. 새 실행 래퍼는 `tools/verify-pressure-window-v25.cjs`이며, 제품 코드를 바꾸지 않았다. 원시 결과는 같은 이름의 JSON과 `docs/v25-qa/pressure-window-coverage.log`에 있다.

35개 전투 구성 × 3난도 × 페이즈 2를 각각 1,440틱, 접근전은 35개 구성 × 3난도를 각각 1,800틱 관찰했다. 총 340,200틱이다. 실제 체크포인트 API로 페이즈를 선택하고 자동 공격·스킬을 끄며 무적을 준 CPU fixture다. 자연 진행 완주나 모바일·브라우저·GPU 성능 검사가 아니다.

| 난도 | 보스 활성 압박막의 연속 충돌 면적 | 접근전 활성 압박막 |
| --- | ---: | ---: |
| 헬 | 66% | 46.2% |
| 노멀 | 44% | 30.8% |
| 여유 | 22% | 15.4% |

모든 105개 보스 사례와 105개 접근전 사례가 기존 엄격한 `1e-10` 오차 기준을 통과했다. 면적은 실제 활성 상태의 가로·세로 충돌 캡슐을 360×640 화면 경계로 잘라 중복을 한 번만 계산한 연속 합집합이다. 설정의 목표값을 읽어 통과시킨 것이 아니다. 추가로 8픽셀 간격으로 전체 실제 탄환·레이저의 합집합을 24틱마다 측정해 JSON에 남겼다.

이 비율은 예고 후 활성화한 압박막의 면적이다. 전투 내내 이 비율을 유지하거나, 모든 공격이 동시에 이 비율을 차지한다는 뜻은 아니다. 다른 실제 탄환과 레이저는 면적을 더할 수 있다. 예고와 잔광은 피해 면적에 포함하지 않는다.

관측 최고값은 탄환 215개, 레이저 13개, 대기 중인 정체성 예고 4개, 최근 예고·발사 기록 5개였다. 각각 기존 상한 768·40 및 새 기록 상한 4·8 이내다. 풀 부족과 그룹 누락은 0이었다. 보스 사례마다 가로·세로·격자 세 구성을 모두 관찰했다. 압박막의 952,479개 틱별 관측에서 최초 예고의 위치·두 끝점·폭·예고 및 활성 경계를 비교했으며 바뀐 항목이 없었다. 보스 활성 시간 360틱, 접근전 180틱, 예고는 90틱(여유 102틱)으로 유지됐다.

10개 적대 행위자 구성에서는 대기 중인 정체성 예고가 있을 때 보스 체력만큼의 아군 탄환을 삽입하는 명시적 패배 fixture로 실제 `hitTarget` 경로를 실행했다. 자동 화력이나 일반 플레이로 이겼다는 뜻은 아니다. 패배한 시전자의 대기열은 비워지고 기존 예고는 취소됐다. 원래 예정 발사 시점 뒤 12틱까지 해당 시전 ID의 탄환·발사 이벤트·살아 있는 예고 계획이 생기지 않았다. 렌더러의 보스 전투 단계 조건과 `cancelled` 계획 제외 조건도 확인했다. 이번 후속 검사는 취소된 이펙트의 실제 픽셀 검증을 별도로 주장하지 않는다.

최초 패배 fixture는 전환 단계에 남아야 한다고 잘못 가정했다. 실제 기존 코드에서는 남은 위험물이 없으면 바로 다음 안전 페이즈로 넘어갈 수 있다. 검사 대상을 패배한 행위자와 기존 시전 ID로 바꿔 두 경로를 모두 확인했다. 제품 코드나 면적 통과 기준은 바꾸지 않았고, 최초 실패 로그는 `pressure-window-coverage-initial-fixture-failure.log`에 보존했다.

검사 전후 `core.js`, `weapon-patterns.js`, `boss-skills.js` SHA-256이 같았다. `core.js` 해시는 `0931918bc6517c6ad73a5f442922765149b35a2d40bd60d32c811cf70950e851`이다.
