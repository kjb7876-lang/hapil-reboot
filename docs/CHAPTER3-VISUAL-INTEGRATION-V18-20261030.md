# 제3부 실제 자산 연결 및 표시 검증

최신 정본 `e069b22f…cabaa`의 u201 → u202 → u204 → u205 → u206 → u203 순서를 따른다. 여섯 장면은 통제 체계의 단계별 전투 역할이며 여섯 명의 새 인물이 아니다. 연결 수치가 소진되면 강제 반복 연결을 끊는다. 기억이나 기억의 문이 파괴되는 효과를 넣지 않는다.

| 본편 index / 표시 그룹 | 장면·역할 | 실제 본체 소스 | 자세 한계 | 배경 |
| --- | --- | --- | --- | --- |
| 12 / 13 | u201 전쟁 관리 | Drive u201-mid 512 atlas | 서로 다른 정적 4자세 | war_loop |
| 13 / 14 | u202 자비 교정 | Drive u202-mid 512 atlas | 서로 다른 정적 4자세 | war_loop |

| 15 / 16 | u205 권한 역전 | Drive u205-mid 512 atlas | 서로 다른 정적 4자세 | war_loop |

다른 캐릭터·보스의 본체를 대신 사용하지 않았다. RC140의 회색 수호 기계를 통제자 본체로 부르지 않았고 사용하지 않았다. 4자세를 새로 생성하지 않았다. 배경은 네 개의 실제 소스 그림을 캐시한 세로 합성이다. 여섯 개의 독립 원화나 충돌 지형을 새로 완성했다는 뜻이 아니다.

준비·조준·발사·회복을 기존 `action`과 실제 성공한 `releaseTick`에 연결했다. 발사 후 12 tick은 발사 자세를 유지한다. u206의 회복은 원래 대기 자세를 사용한다. 피벗은 실제 픽셀을 본 뒤 추정한 수동 몸통 앵커다. 23개 원본 자세의 앵커가 실제 불투명 몸통 픽셀(알파 247~255)에 놓이는지도 검사했다. 물리 피벗이 원작에서 인증된 것은 아니다. 모든 자세에 같은 원본 픽셀 배율을 사용하고 전투 좌표는 바꾸지 않는다.

일반 적은 실제 demon_drone의 대기·공격·파괴 3소스다. 이동·피격 전용 그림이 없으므로 그때는 대기를 유지한다. 주변의 흰 원이나 타 보스 스프라이트를 추가하지 않는다. 현재 코어가 살아 있는 적만 그리므로 파괴 그림은 로딩 계약과 명시적 파괴 상태를 지원하지만 자연 진행에서 보이는 파괴 애니메이션을 완성했다고 주장하지 않는다.

탄환과 레이저는 같은 통제 체계의 control-lance/beam만 사용한다. 실제 그림의 밀도 높은 영역이 기존 피해 캡슐 내부를 채운다. 창의 전체 끝·날개·전기 외곽은 별도 소스 오버레이로 남겨 판정 밖 장식에 투명 픽셀이 생겨도 피해 내부가 비지 않는다. 미검증 도형 대체나 새로운 불투명 배경은 없다. 1~4장면은 실제 본체의 청록·금속·황동 계열, 이주 코어는 청록·강철색, 통제자는 자주·청색 계열로 구분한다. 색상 처리는 소스 알파와 밝기 변화를 보존한다. 작은 탄환의 모양은 기존 판정 때문에 원·캡슐 윤곽을 유지한다. 그것을 독립 완성 탄환 애니메이션이라고 부르지 않는다.

실제 발사 이벤트에만 전용 창의 준비·발사 강조를 연결했다. 시전·스킬은 원래 상한 4/8 draw와 2MiB 캐시를 유지한다. 탄환은 최대 4MiB, 배경은 한 장 360×720 RGBA=1,036,800B 캐시다. 원본 이미지 디코드 메모리는 이 캐시 수치에 포함되지 않는다.

`chapter3-visuals-v18.test.cjs` 3건은 실제 PNG/WebP를 CPU Canvas로 디코딩하고 6그룹 전체의 본체·필수 탄환·배경·3드론 상태, 누락 시 중단, 발사 자세, 위치 보존, 피해 내부 불투명도와 캐시 상한을 검증했다.

`CHAPTER3-VISUAL-CPU-20261030.json`은 무적·자동공격 중지 fixture에서 실제 1,800 tick×12 관찰의 phase3 peak/release를 가져왔다. NORMAL/HELL×6장면×2snapshot×2quality의 48개 장면, 워밍업 5회 뒤 각 30회 총 1,440회의 CPU 렌더를 측정했다. 모든 탄환·활성/사라짐 레이저의 자산 표시 개수가 일치했고 소스 누락, poolPressure, droppedGroups는 0이었다. 반복 정적 렌더 p95는 0.62~6.46ms였다. `docs/chapter3-v18-pixels/contact.jpg`의 실제 화면 픽셀을 직접 확인했다.

이 수치는 실제 브라우저, 소프트웨어/실제 GPU, 모바일 에뮬레이션·실제 기기, 자연 클리어, 네트워크·초기 디코드, 시뮬레이션 성능 검사와 구분한다. 그 검사를 통과했다는 의미가 아니다. 원본/다운로드/런타임 SHA-256과 바이트 복사 대조는 `CHAPTER3-SOURCE-DISCOVERY-20261030.json`과 `CHAPTER3-RUNTIME-ASSETS-V18-20261030.json`에 기록했다. 상류 파생 설명의 옛 경로는 출처 기록으로만 보존하며 현 환경의 존재 경로는 별도로 확인했다.
